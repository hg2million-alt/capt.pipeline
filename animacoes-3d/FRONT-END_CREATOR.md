# PROMPT BASE — CRIAÇÃO DE LANDING PAGE PROFISSIONAL

Quero criar uma landing page profissional, moderna, responsiva e otimizada para conversão para o meu projeto.

Você será responsável por me ajudar a planejar, estruturar, projetar e posteriormente implementar o site de forma profissional.

## 1. OBJETIVO PRINCIPAL

O projeto será uma landing page **frontend-only**, sem backend, banco de dados, sistema de login ou painel administrativo, a menos que eu solicite explicitamente alguma dessas funcionalidades posteriormente.

O objetivo principal do site é apresentar o negócio/produto/serviço de forma profissional e gerar conversões, principalmente através de CTAs de contato, orçamento, WhatsApp, formulário externo ou outra ação que eu definir durante o projeto.

Não quero que você simplesmente gere um site genérico baseado em padrões de IA.

Quero que o projeto tenha:

* identidade visual própria;
* hierarquia visual clara;
* aparência profissional;
* excelente experiência em desktop e mobile;
* boa conversão;
* carregamento rápido;
* código organizado;
* componentes reutilizáveis;
* acessibilidade básica;
* SEO técnico básico;
* conteúdo coerente com o negócio;
* visual consistente entre todas as seções.

---

# 2. COMO DEVEMOS TRABALHAR

Não quero que você tente decidir todo o projeto de uma única vez.

Vamos construir o projeto progressivamente.

Antes de implementar qualquer coisa importante, devemos definir e validar:

1. negócio;
2. público-alvo;
3. objetivo da landing page;
4. identidade visual;
5. referências visuais;
6. estrutura das seções;
7. conteúdo;
8. CTAs;
9. comportamento responsivo;
10. detalhes de interação;
11. implementação;
12. revisão e refinamento.

Sempre que houver uma decisão importante de design, explique brevemente a recomendação e aguarde minha aprovação quando necessário.

Se eu fornecer uma referência visual, use-a como referência de direção estética e estrutura, mas NÃO copie literalmente o design.

Adapte a referência ao meu projeto.

# 4. IDENTIDADE VISUAL

A identidade visual deverá ser definida com base no negócio e nas referências que eu fornecer.

Considere:

* cores;
* tipografia;
* estilo fotográfico;
* iconografia;
* bordas;
* espaçamentos;
* botões;
* cards;
* elementos decorativos;
* tratamento das imagens;
* composição;
* contraste;
* hierarquia visual.

Evite criar um visual genérico de "site feito por IA".

A identidade deve parecer criada especificamente para o negócio.

Se eu não fornecer uma identidade visual, proponha uma direção visual coerente com o segmento e explique rapidamente o motivo.

---

# 5. DIREÇÃO DE DESIGN

Priorize:

* design moderno;
* aparência profissional;
* excelente hierarquia visual;
* bastante respiro;
* tipografia bem definida;
* espaçamentos consistentes;
* contraste adequado;
* composição equilibrada;
* CTAs visualmente claros;
* responsividade real.

Evite:

* excesso de gradientes;
* excesso de sombras;
* excesso de cards;
* excesso de elementos decorativos;
* aparência exageradamente tecnológica quando não fizer sentido;
* interfaces visualmente poluídas;
* textos enormes sem necessidade;
* seções repetitivas;
* componentes genéricos;
* excesso da cor principal;
* efeitos apenas para "deixar bonito".

Cada elemento deve existir por algum motivo.

---

# 6. ESTRUTURA DA LANDING PAGE

A estrutura NÃO precisa seguir um modelo fixo.

Defina as seções de acordo com o objetivo do negócio.

Possíveis seções:

* Header;
* Hero;
* Benefícios;
* Sobre;
* Serviços;
* Produtos;
* Como funciona;
* Diferenciais;
* Processo;
* Portfólio;
* Galeria;
* Depoimentos;
* FAQ;
* Localização;
* CTA final;
* Footer.

Não adicione uma seção apenas porque ela é comum em landing pages.

A estrutura deve ser justificada pela necessidade do projeto.

---

# 7. HERO

O Hero deve ser tratado como uma das partes mais importantes da página.

Ele deve comunicar rapidamente:

* o que o negócio oferece;
* para quem;
* principal benefício/diferencial;
* ação desejada.

Evite excesso de texto.

O Hero deve possuir uma composição visual forte e profissional.

Dependendo do projeto, podemos utilizar:

* fotografia;
* imagem de produto;
* composição gráfica;
* ilustração;
* mockup;
* imagem gerada;
* background fotográfico;
* composição editorial;
* elementos abstratos.

A escolha deve depender do segmento.

O CTA deve parecer parte da interface do site e não um elemento artificial colocado dentro de uma imagem.

---

# 8. CONTEÚDO

O conteúdo deve ser:

* claro;
* direto;
* natural;
* convincente;
* adequado ao público;
* escrito em português brasileiro quando o projeto for brasileiro.

Evite:

* textos genéricos;
* frases vazias;
* excesso de palavras;
* clichês de marketing;
* promessas que o negócio não pode comprovar.

Se eu fornecer textos, preserve a intenção original e melhore apenas quando necessário.

Se precisar criar textos, deixe claro quando forem sugestões.

---

# 9. IMAGENS

Quando imagens forem necessárias, defina:

* tipo de imagem;
* proporção;
* enquadramento;
* posição do objeto;
* iluminação;
* ambiente;
* estilo;
* espaço negativo necessário para textos;
* comportamento no mobile.

Se uma imagem for utilizada no Hero, considere desde o início a composição para desktop e mobile.

Não escolha imagens apenas porque são bonitas.

A imagem precisa contribuir para a comunicação da marca.

---

# 10. RESPONSIVIDADE

A página deve ser desenvolvida pensando primeiro na experiência real do usuário.

Não quero simplesmente um desktop "encolhido" no mobile.

Considere individualmente:

* navegação;
* header;
* menu mobile;
* Hero;
* imagens;
* textos;
* botões;
* grids;
* cards;
* espaçamentos;
* ordem dos elementos;
* tamanhos de fonte;
* largura máxima;
* overflow;
* elementos decorativos.

A interface deve funcionar muito bem em:

* celulares pequenos;
* celulares grandes;
* tablets;
* notebooks;
* desktops;
* telas grandes.

Evite quebras de layout.

---

# 11. TECNOLOGIA

Quando chegarmos à implementação, utilize uma stack moderna e simples.

Preferência:

* React;
* Vite;
* npm;
* Tailwind CSS quando fizer sentido;
* Framer Motion quando animações forem realmente úteis.

Não adicione dependências desnecessárias.

A landing page deve permanecer frontend-only.

Não criar:

* backend;
* banco de dados;
* autenticação;
* painel administrativo;
* APIs próprias;

a menos que eu solicite explicitamente.

---

# 12. ANIMAÇÕES

As animações devem ser discretas e utilizadas para melhorar a experiência.

Podem incluir:

* fade;
* reveal;
* pequenas transições;
* hover;
* microinterações;
* animações de entrada;
* transições suaves entre estados.

Evite:

* animações exageradas;
* elementos pulando;
* excesso de movimento;
* efeitos que prejudiquem performance;
* animações que dificultem a leitura.

A página deve continuar parecendo profissional mesmo com as animações desativadas.

---

# 13. SEO

Mesmo sendo frontend-only, implemente uma boa base de SEO.

Considerar:

* title;
* meta description;
* headings corretos;
* hierarquia H1/H2/H3;
* alt text;
* URLs adequadas;
* sitemap.xml;
* robots.txt;
* canonical;
* Open Graph;
* Twitter/X cards quando aplicável;
* dados estruturados quando fizer sentido;
* conteúdo semântico.

Não faça keyword stuffing.

O conteúdo deve ser escrito primeiro para pessoas e depois otimizado para mecanismos de busca.

---

# 14. PERFORMANCE

Priorize:

* imagens otimizadas;
* lazy loading quando apropriado;
* poucos scripts;
* poucos pacotes;
* componentes eficientes;
* fontes bem carregadas;
* redução de JavaScript desnecessário;
* boa experiência em conexões lentas.

Evite colocar efeitos ou bibliotecas que não tragam benefício real.

---

# 15. ACESSIBILIDADE

Considere:

* contraste;
* textos legíveis;
* navegação por teclado;
* estados de foco;
* labels;
* alt text;
* HTML semântico;
* aria apenas quando necessário;
* áreas clicáveis adequadas;
* respeito a `prefers-reduced-motion`.

---

# 16. COMPONENTIZAÇÃO

O código deve ser organizado.

Separe componentes quando isso melhorar:

* manutenção;
* reutilização;
* legibilidade;
* organização.

Evite tanto:

* um único componente gigantesco;

quanto:

* dezenas de componentes desnecessários.

A arquitetura deve ser proporcional ao tamanho do projeto.

---

# 17. QUALIDADE VISUAL

Antes de considerar a página finalizada, faça uma revisão visual completa.

Verifique:

* alinhamentos;
* espaçamentos;
* tamanhos;
* contraste;
* consistência;
* responsividade;
* hierarquia;
* CTAs;
* imagens;
* tipografia;
* estados de hover;
* menu mobile;
* possíveis overflow;
* elementos quebrados;
* seções excessivamente longas;
* repetição visual.

A página deve parecer um projeto profissional feito sob medida, e não um template genérico.

# 19. REGRA IMPORTANTE SOBRE ALTERAÇÕES

Durante o desenvolvimento, eu posso mudar decisões anteriores.

Quando eu solicitar uma alteração:

1. identifique exatamente o que mudou;
2. preserve o que já foi aprovado;
3. não altere outras partes sem necessidade;
4. verifique se a alteração afeta desktop ou mobile;
5. verifique se afeta outras seções;
6. implemente somente o necessário;
7. revise visualmente depois.

Não "reinvente" o site inteiro porque uma pequena alteração foi solicitada.
